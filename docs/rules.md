# 编码规范（Rules）

> 范围：本文件只记录**可复用的通用规则**与**本项目特有的禁用写法/检查项**，不记录一次性任务细节。
> 文档结构门禁回填（2026-09-22）：按 vibe-coding-workflow skill 必需章节重组。

## 默认规则（创建即生效）
- **分层与边界**：接口层（HTTP handler / admin REST）、业务层（调度、轮询、熔断、路由）、数据访问层（落盘 JSON / 加密存储）职责分离；禁止把业务逻辑堆进入口文件（`proxy.go` 已 2184 行，新增逻辑应独立成文件）。
- **配置集中**：环境变量与配置项集中定义、集中读取；禁止在业务代码中散落硬编码常量或魔法数字。
- **错误不静默**：关键流程必须有明确错误处理，禁止 `_ = err` 静默吞错或以空实现掩盖失败。
- **输入先校验**：对外输入（HTTP 请求体、admin API 参数、落盘文件内容）必须先校验再进入业务逻辑；上游返回的 JSON 一律视为不可信。
- **函数单一职责**：复杂函数拆分为小函数；新增代码保持低耦合、可单测。
- **改动前定范围、改动后必验证**：变更前确认影响面与回归范围，变更后至少有一条可复现验证（命令 / 测试 / 输入输出样例）。

## 命名规范
- 使用有语义的命名；禁止 `tmp`、`test1`、`data2` 等无意义命名进入正式代码。
- Go 侧遵循社区惯例：导出标识符用 `CamelCase`，未导出用 `camelCase`；缩写词保持大小写一致（如 `APIKey`、`TTFBTimeout`、`dispatchGroupName`）。
- 测试函数命名为 `Test<被测单元>`，语义化描述被测行为；测试文件与被测文件同目录、同包（`package app`）。
- 渠道组保留名使用双下划线前缀标识系统保留（如 `__cline_pool__`），避免与用户配置的业务组名冲突。

## 代码风格
- 统一用 `gofmt` 格式化；提交前应保证新增/修改文件 `gofmt -l` 为空。
- 优先小函数、低耦合、显式优于隐式；避免过深嵌套（早返回代替多层 if）。
- 新代码采用现代 Go 写法：`atomic.Bool`、`sync.OnceFunc`、`slices`/`maps` 包、内建 `min`/`max`、`any`、`json` 的 `omitzero`；**存量代码不整片重写**（只对生成/改动的代码应用新风格）。
- 并发原语优先标准库：细粒度互斥用 `sync.Mutex` + map，fan-out 用 `errgroup` 并 `SetLimit` 限流；不允许无退出路径的 goroutine。
- 路由使用 Go 1.22+ method-aware `ServeMux` + `r.PathValue`，不引入第三方路由框架。

## 错误处理
- 错误信息须可定位：包含上下文（账户标识、渠道 ID、上游状态码、URL 等），并返回明确失败状态，禁止无信息量的 `errors.New("failed")`。
- 错误分派用 sentinel error + `errors.Is` / `errors.As`（如 `ErrRateLimited{RetryAfter}`、`ErrKeyInvalid`、`upstreamStatusError`），禁止字符串匹配判错。
- 需要上游状态码参与决策时（如是否换渠道重试），必须用类型化错误承载并保证 `Error()` 输出与原文本兼容，避免日志可读性回退。
- 多处失败聚合使用 `errors.Join`，不丢失任一子错误。
- 中间件包装 `http.ResponseWriter` 时必须透传能力接口（`http.Flusher`，未来可能的 `http.Hijacker`），否则 handler 侧能力断言失败；新增包装层必须同步补测试。
- 对 `map[string]any` 取值后禁止直接 `.(string)` 裸断言用于日志/展示路径，必须 `, ok` 双返回或 `fmt.Sprintf("%v", ...)`。

## 日志与注释
- 日志覆盖关键路径：请求分发、渠道选择与切换（failover）、熔断状态变更、鉴权失败、外部探活结果；日志中不得输出 token / 密钥明文。
- 注释写"为什么"（设计取舍、边界原因、协议差异），不重复"做了什么"；复杂分支与兼容性处理必须写明动机。
- 对外可见行为变更（开关、默认值、错误语义）必须在文档中留痕，不能只靠代码自解释。

## 安全与隐私
- 禁止提交密钥、OAuth token、密码等敏感信息；凭据落盘必须加密（AES-GCM），禁止明文写入配置文件。
- 新增凭据类字段（token / key）落盘必须走 secretbox（`enc:v1:`）+ 旧版明文自动迁移；迁移须幂等，单字段解密失败仅置空并告警，不得导致整体加载失败。
- 新增开关默认值必须**向后兼容**（如灰度开关默认关闭 = 回退态），避免静默改变线上行为。
- admin 侧接口一律过鉴权（Strict 级：无 token 一律 401）；写操作与高风险动作需人工确认，fail closed。
- 审计记录 append-only，不可篡改；记录"谁 / 何时 / 改了什么 / 依据"。

## 测试与回归要求
- 至少覆盖主流程与一个失败分支；新增可配置开关须有"默认值不改变既有行为"的测试。
- 涉及路由选择 / 熔断 / 重试的改动，用 `httptest.NewServer` 搭假上游做全链路测试，**不 mock `http.Client`**（避免测到假实现）。
- 门禁：`go build ./...`、`go vet ./...`、`go test ./...`、`go test -race ./...` 必须全绿；-race 由 CI 执行（本地 proot 环境 TSan 不可用）。
- 测试必须可重复（不依赖外网、真实凭据或时序运气）；需要外部依赖的测试应显式跳过并说明原因。
- 涉及凭据加密的测试必须隔离主密钥（`t.Setenv(envMasterKey, ...)` 或 `t.Chdir(t.TempDir())`），禁止在仓库目录生成/读取真实 `.masterkey`。

## 禁止事项（反模式）
- 禁止跨层直接调用导致耦合失控（如数据访问层反向调用 HTTP handler）。
- 禁止为"顺手"扩大改动范围：格式化全仓、升级大版本依赖、重构无关模块都不应混入功能性 commit（保持 1 WP = 1 commit 的可回滚性）。
- 禁止在未提供回滚方案的前提下实施高风险变更（架构调整、鉴权、加密迁移、CI 发布流程变更）。
- 禁止用"文档已更新"替代事实核对：文档中描述的结构 / 行数 / 文件清单必须与仓库实际一致。
- 禁止跳过顺序依赖（M 级不得跳级推进）与门禁检查（测试未过不得发布）。
